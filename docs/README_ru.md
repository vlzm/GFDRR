# Документация — с чего начать

Проект — симулятор системы проката велосипедов, построенный на реальных
данных Citi Bike. На входе — месяц поездок; симулятор проигрывает этот спрос
период за периодом, и каждое изменение записывается одной строкой в журнал
flow-событий — таблицу, в которую строки только добавляются и которая одна
хранит всю историю запуска. Текущая фаза — прогнозирование спроса: модель
предсказывает будущий спрос, и симулятор работает на этом прогнозе рядом с
базовым воспроизведением истории. Поэтому канонический сценарий — два
запуска: базовое воспроизведение в `notebooks/test_pipeline.ipynb` и запуск
на прогнозе в `notebooks/forecast_pipeline.ipynb`; всё в кодовой базе обязано
служить одному из них.

Выбери дверь по тому, зачем ты пришёл.

## Запустить

[quickstart.md](getting-started/quickstart.md) ведёт от чистого клона до первого журнала
flow-событий за несколько минут, на синтетическом сценарии — без скачивания
данных. Та же страница заканчивается вариантом на реальных данных: откуда
берутся CSV поездок, сколько они весят, какой командой скачать месяц.

## Понять

Три коротких чтения, от конкретного к общему:

1. [concepts.md](concepts.md) — пять понятий, на которые опирается каждая
   другая страница: период, спрос, инвентарь станции, журнал flow-событий,
   артефакт запуска.
2. [worked-examples.md](key-components/worked-examples.md), сценарии 1–3 — самые маленькие
   настоящие таблицы журнала: потеря спроса без велосипеда, поездка с
   постановкой в док в тот же период, поездка с постановкой периодом позже.
   Каждую таблицу там заново прогоняет тест.
3. [architecture.md](explanation/architecture.md) — система в диаграммах на
   трёх масштабах, в конце — полная карта модулей.

## Изменить

Для частых задач есть рецепты в [how-to/](how-to/) — по одной странице:
задача, шаги с настоящими командами и файлами, ожидаемый результат.

- [change-the-demand.md](how-to/change-the-demand.md) — изменить масштаб
  спроса или проиграть другой месяц.
- [run-on-a-forecast.md](how-to/run-on-a-forecast.md) — запустить симулятор
  на сохранённом прогнозе вместо истории.
- [add-a-table-to-the-run-artifact.md](how-to/add-a-table-to-the-run-artifact.md)
  — добавить заранее посчитанную таблицу в каждый сохраняемый запуск.
- [debug-an-invariant-violation.md](how-to/debug-an-invariant-violation.md)
  — понять, какой инвариант (I1–I5) нарушен и какие строки журнала смотреть.

Новый рецепт появляется, когда одна и та же задача возникла дважды. Для
изменения без рецепта найди изменяемую часть на карте модулей в
[architecture.md](explanation/architecture.md) и открой её документ:

| Часть | Документ |
|---|---|
| сырой CSV поездок → входы симулятора | [data-model.md](key-components/data-model.md) |
| цикл симуляции | [simulation-engine.md](key-components/simulation-engine.md) |
| перевозка велосипедов грузовиками | [rebalancing.md](key-components/rebalancing.md) |
| библиотека журнала (`gbp/model/flows.py`) | [flow-journal.md](key-components/flow-journal.md) |
| артефакты запусков и веб-интерфейс | [visualization.md](key-components/visualization.md) |
| API артефактов запусков | [api.md](reference/api.md) |
| прогнозирование спроса | [ml-toolkit.md](key-components/ml-toolkit.md) |

Каждый документ заканчивается секцией «Why It Is Built This Way»: несущие
решения, для каждого — отвергнутая альтернатива и причина. Решения, которые
затрагивают несколько модулей, лежат короткими записями в
[decisions/](decisions/).

## Найти точный контракт

[Notations.md](../Notations.md) (корень репозитория) — словарь проекта:
каждая колонка, каждый статус, каждое имя таблицы — одно понятие, одно слово.
Открывай его по разделам, когда нужен контракт; это справочник, а не маршрут
чтения. Контракт HTTP — в [api.md](reference/api.md); список команд — в
корневом [README.md](../README.md).

## Остальное в docs/

- `key-components/` — документы по модулям из таблицы выше.
- `how-to/` — рецепты задач из двери «Изменить» выше, плюс
  [set-up-osrm.md](how-to/set-up-osrm.md): необязательный
  маршрутный сервер на дорожном графе.
- `decisions/` — короткие записи о проектных решениях, которые нельзя
  вывести из кода, одна запись — одно решение.
- `plans/` — планы текущей работы.
- `reports/` — сохранённые отчёты об оценке моделей и ревью.
- `method/` — личные заметки автора о методе работы.
  [comprehension_levels_ru.md](method/comprehension_levels_ru.md) описывает
  способ читать кодовую базу по пяти уровням понимания — чтение для
  интересующихся, не часть маршрута выше.

## Языки

Канонический язык документов — английский. Русская версия (`*_ru.md`) есть
только у файлов, которые автор регулярно перечитывает: у этой страницы
(каноническая версия — [README.md](README.md)), у
[comprehension_levels.md](method/comprehension_levels.md) и у
[working-method.md](method/working-method.md). Каждая пара держится
синхронной.
